# Plan for #4: Filter runs by vehicle on the web page

## Goal
Add a labelled vehicle filter to the web page so users can narrow the visible
run rows by vehicle ID and clear it to restore all rows. Keep the existing API,
run creation flow, and seeded data unchanged.

## Dependencies (confirmed / plausible / open), each with change: yes | no
- **Confirmed — `public/index.html` (yes):** owns the runs table, initial
  `/api/runs` load, and row rendering; add the filter control and filtering
  behavior here.
- **Confirmed — `e2e/smoke.spec.ts` (yes):** existing Playwright UI coverage;
  add a browser test for typing `WVW-1001` and checking only its two rows.
- **Confirmed — `test/app.test.ts` (no):** API filtering is already covered by
  the `GET /api/runs?vehicleId=` test; no endpoint change is required.
- **Confirmed — `src/app.ts` and `src/runs.ts` (no):** the existing API and
  `RunStore.list` already support vehicle filtering.
- **Confirmed — `src/config.ts`, `k8s/configmap.yaml`, `README.md` (no):**
  this is a browser-only change and adds no environment variable.
- **Plausible — `package.json` / Playwright config (no):** existing e2e
  command and browser setup should run the new spec; verify while testing.
- **Open — none.**

## Tests
- `e2e/smoke.spec.ts`: add a test that loads the page, types `WVW-1001` into
  the labelled filter, asserts exactly two visible rows, and verifies clearing
  restores all seeded rows.
- Run `npm run verify` and `npm run e2e` with the server running.

## Environment contract
No variables are added or changed; `src/config.ts`, `k8s/configmap.yaml`, and
the README environment table remain unchanged.

## Risks
- Filter matching must update every rendered row without breaking the add-run
  refresh path.
- Playwright locators must use the required accessible label/roles.
- Pipeline risks are limited to the unit/type/build gates and the browser gate;
  deployment, rollout, stability, and smoke behavior should be unchanged.

## Open questions
None.
