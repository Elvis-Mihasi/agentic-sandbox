# Plan — Issue #1: GET /api/vehicles listing distinct vehicle IDs

## Goal
Expose `GET /api/vehicles` returning the distinct `vehicleId` values that have at
least one run, sorted ascending, with no duplicates, so clients avoid paging
through all runs.

## Files to change
- `src/runs.ts` (confirmed): add `RunStore.vehicleIds()` returning distinct
  `vehicleId` values sorted ascending. Domain logic belongs here per
  `.github/instructions/src.instructions.md`.
- `src/app.ts` (confirmed): add `GET /api/vehicles` route delegating to the store.
- `test/app.test.ts` (confirmed): unit tests for seeded data and empty store.
- `README.md` (confirmed): add the endpoint to the API table.

## Tests to add
- Seeded store: `["WVW-1001","WVW-2042","WVW-3310"]` — distinct + sorted, 200.
- Empty store: `[]`, 200.

## Risks
- Low. Read-only endpoint, no new dependencies, no env vars (no configmap/README
  contract change needed).

## Open questions
- "Sorted ascending" assumed to be default lexicographic string sort; all IDs are
  ASCII so this matches numeric ordering of the suffix.
- Response is a bare JSON array of strings, matching the ticket example and the
  shape of `GET /api/runs`.
- Empty store answers `[]` with 200, not 404, consistent with `GET /api/runs`.
